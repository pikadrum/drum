# 引き継ぎ：ドラム練習スコープ（ドラム側）

このファイルは、ドラム側の作業を続ける会話と、鍵盤側（keys）の作業をする会話の両方が読みます。
- **ドラム側の会話**：作業を始める前に、これと鍵盤側の引き継ぎを読む。変えたことがあれば、ここを更新する。
- **鍵盤側の会話**：同期まわりの決まりとドラム側の動きを知るために読む。このファイルと、ドラム側のソフトのファイルは書き換えない。
- **同期の約束ごと**：正式なものは `同期の仕様.md`（このリポジトリのいちばん上）。仕様を変えるときは、ドラム側の会話で直す。

## ドラム側の作業の決まり
- PC版とスマホ版の両方に入れる。
- 機能を変えたら、配布ページと、ソフトの「このソフトについて」の説明も直す。
- 直したら、`<script>` を取り出して `node --check` で構文を確かめ、Playwright のスクリーンショットで画面を確かめる。
- 1行のコードの中のコメントは `/* */` で書く。
- 設定のいちばん下の「ビルド YYYY/MM/DD HH:MM」を、日本時間で更新する。
- GitHub に上げる前に、返事の最後に文章で聞く（確認の画面は出さない）。上げたら、返事に配布ページのURLを書く。
- ファイルは「出して」と言われたときだけ渡す。
- 返事は日本語。

## 主な機能（2026/10/23 時点）
- MIDIファイルをドラム譜にして再生。表示は「譜面」「グリッド」「ゲーム（縦に落ちる）」。グリッドは画面の左下のボタンで横スクロールにもできる。
- 叩いた判定：◎PERFECT、○GOOD（早い＝水色、遅い＝橙）、×BAD（違うパッド・ずれすぎ・音符のない所。×は叩いた位置に出し、音符には移さない＝2026/10/24 から。前は近くの外した音符に移していて、×が消えたように見えた）、△MISS（叩かなかった）。判定は、その再生で最初に叩いた所から始まる。「DT-1風」（正解は青、外れは赤）にも切り替えられる。
- ハイハットはオープンとクローズを区別して判定。ライド・シンバル・スネア・タムの叩き分け（カップ・エッジ・リムショット・クロススティック）は、判定では区別しないが、表示と音で分ける。
- 追加のパッド AUX1〜6（キーは G・H・T・Y・B・N。役割：スプラッシュ・チャイナ・カウベル・タム4・タム0・スネア2・キック2。番号は「叩いて覚える」）。
- ミキサー、ループ、テンポ、カウント、メトロノーム（4分・8分・3連・16分・6連を重ねる、裏だけ、好きな位置にアクセント）、メトロノーム専用モード。
- 採譜（設定の「✎ 編集」「🖨 楽譜出力」の隣）：叩いた音をそのまま譜面に。クリック・開いていた曲・音楽ファイルに合わせて録れる。あとで小節線とテンポを合わせ直せる。MIDIで保存。採譜中は下にパッドが出るので、譜面はパッドに隠れない所に入る段数に減らす（音符が小さくなりすぎない範囲。終わると元の段数に戻す）。
- 編集・MIDIの書き出し（「今聞いている音で保存」でミキサー・カウント・メトロノームを反映）、楽譜のPDF・印刷・画像、伴奏のMusicXML。
- 最初の画面のドラムセット（押した場所で叩き分け、ドラッグで配置・大きさを変えられる）。スマホの横画面では出さない。ハイハットはクローズ・オープンHH・ハーフHH（ハーフオープンの音、判定はオープンと同じ。2026/10/24）。縦画面のライドはハイハットと同じ大きさ。
- 画面のパッドの叩き分け（2026/10/24）：ライドとクラッシュの真ん中はカップ（クラッシュはカップの番号がないので、番号はふつうのまま音と表示だけカップ）。ハイハットのふちはとても広い（半径の2割4分より外。真ん中だけがふつうの音）。スネアのリムは下側の3時〜7時のふちだけ（4時〜6時はパッドの外側まで、ふちの幅の2倍広げて受ける。見た目は変えない）。タム・フロアはリムなし（電子ドラムからのリムの信号はそのまま受ける）。
- 左右クラッシュの音：2026/10/23 にはっきり分けたが、ユーザーの希望で 2026/10/24 にいちばん最初の音（ノイズだけ。右は少し低く短い）に戻した。
- キック2を出しているときは、キックの表示を「キック1」にし、縦画面ではキック1とキック2の場所を入れ替える（大きさはそのまま）。ライドのボウはチップで叩いた硬い「チン」の音（2026/10/24）。
- 最初の画面のパッド（2026/10/24）：MIDI入力がないときは、AUXの設定に関係なくスプラッシュ・チャイナ・カウベル・タム4・キック2を出す（その役割のAUXがあればそのAUX、なければ音だけのパッド `r_役割`）。タム0とスネア2は出さない。MIDI入力があるときは、AUXでオンにしたものだけ（番号がなくても出す）。
- 再生中の段の入れ替え：1段2小節以下は、今の段が半分進んだら、いちばん古い段を次の段にする（1段1小節でも、小節の半分で次の小節が出る。2026/10/24）。3小節以上は最後の小節に入ったら。
- 電子ドラムのハーフオープン（2026/10/24）：CC4（ペダルの開き具合）を覚えておき、オープンの番号（46・26）が来たとき CC4 が境目以下ならオープンHH、大きければハーフHH を光らせる。ユーザーの TD-17 では開ききって 0、踏み込んで 90。境目は設定の「MIDI入力」で変えられる（S.hhOpenMax、初めは10。横にペダルの今の値を出す）。判定はどちらもオープン。
- 曲（MIDIファイル）の再生では、叩き分けの音は 53（ライドのカップ）と 37（クロススティック）だけ（`PLAY_ART`）。40 はふつうのMIDIではエレクトリック・スネアなので、リムの音で鳴らすとスネアが全部「チチチ」になった（2026/10/26 に修正）。電子ドラム・画面のパッドで叩いた音は今まで通り叩き分ける。
- バージョンの番号は付けず、ビルドの日付を使う（ユーザーの決定、2026/10/26）。最初の画面のドラムの絵の右下に、設定の「ビルド」と同じ日付（年月日）を小さく出す（`#padVer`）。
- AUX の役割に「キック2」（キックより低く長い音、GM 35）を追加（2026/10/24）。
- スマホ：横画面で譜面を触ると上下の欄が隠れる、横画面で触ると全画面（Android）、戻るボタンで開いている画面を閉じる。

## 同期の実装（ドラム側）
仕様は `同期の仕様.md` のとおり。ドラム側は `app:"drum"`。
- 同じ端末は BroadcastChannel `pikadrum-sync`、別の端末は PeerJS 1.5.4（部屋番号4〜8桁）。両方につながっていれば中継する。
- 時計合わせは tping/tpong を8回、往復が最小の回のずれを使う。
- `state` は、再生・停止・位置・テンポ・ループが変わったときに送る（50ミリ秒ごとに自分の状態を見て、変わっていたら送る）。
- **ループの頭に戻るときは、各端末が自分で折り返し、`state` を送らない**（鍵盤側と同じ）。再生中のずれは、ループの長さで折り返して比べる。
- `tick` はリーダー（最後に操作した端末）だけが1秒ごとに送る。8ms以下は何もしない、250msまでは1回最大10msずつ半分戻す、それより大きければ鳴らし直す。
- `plays` は `{drums:true, channels:[]}`。相手の `plays.channels` のチャンネルを自分の伴奏からミュートする（設定で切り替え）。
- `song`：MIDIファイルを開いたら送る。受け取ったら開く（設定で切り替え）。**内蔵の練習パターンと、採譜で作った曲は送らない。**
- ドラム側だけの type：`metro`（メトロノームの音色・鳴らし方・アクセント。音量は送らない）と `mm`（メトロノーム専用モードの開始・停止・テンポ・拍子と1拍目の時刻）。鍵盤側は無視してよい。
- MIDIクロックの送受信（DAW向け）もある。鍵盤側は関係しない。

### 鍵盤側と合わせて確認したこと（2026/10/23）
- 小節の数え方：どちらも曲の最初（ティック0）を1小節目、拍子記号がなければ4/4。弱起も特別扱いしないので同じ。「最初の空白の小節を表示しない」設定でも小節番号は元のまま。
- 鍵盤側の「待つ」モード中は、鍵盤側が止まってもドラム側は進む。止まるときに `playing:false` の `state`、動き出すときに位置付きの `state` を送れば、ドラム側も止まってついていく（鍵盤側への提案。鍵盤側はまだ入れていない。入れるのは鍵盤側の作業で、ドラム側は今のままでついていける）。
- ドラム側と鍵盤側を実際につないだテストは、まだしていない。

### 鍵盤側からの提案・確認への答え（2026/10/26）
- 「分けて出す」のカウント：ドラム側はカウント（countNode）もメトロノームと同じく左だけから出る。Playwright で左右の音の大きさを測って確かめた（カウント中は左 0.28、右 0）。
- 「待つ」モードの判定：相手が止めた位置（`SYNC.pausedAt`）の近く（0.6秒以内）から動き出したときは、`resetJudge` をせず `st.hitFrom` もそのまま（続きとして判定する）。前は動き出すたびに直前0.2秒の叩いた印が消え、判定の始まりもやり直しになっていた。違う位置から動き出したときは今まで通りやり直す。
